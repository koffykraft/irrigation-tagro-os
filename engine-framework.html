TAGRO OS · IRRIGATION · LOGICAL ENGINE v1.0

Ask only what this decision needs.

The irrigation OS does not run a universal questionnaire. It identifies the farmer's present task, reuses existing evidence, asks the easiest consequential questions, stops at the requested information depth, and declares honestly how mature the resulting solution is.

Default

SUB-MINIMUM by defaultNo universal formExisting evidence firstHard gates cannot be inventedFarmer may stretch deeper

Engine flow

Need → task profile → dependencies → missing consequential facts → easiest useful question → evidence + provenance → candidate solution → dependency check → provisional result → optional stretch → decision → accepted design → installed reality

Question depths

SUB_MINIMUM gives quick useful direction without false precision. MINIMUM supports a defensible task result. ADEQUATE supports normal design work. STRETCH spends extra farmer effort on optimization. MAXIMUM is reserved for complexity, consequence or explicit preference.

Pages follow the task

A pump check can assemble Pump + Demand + Route/Head without forcing Crop/Soil or BOM. A lateral-length check can assemble Device + Spacing + Lateral + Terrain. A purchase list can assemble Accepted Network + BOM + Catalogue. Page order never controls engineering order.
